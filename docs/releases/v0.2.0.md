# loundrycode v0.2.0

v0.2 turns the foundation into the first usable logic layer for project generation.

## included

- fixed the swift string-interpolation failure in `LoundryOrchestrator`
- fixed the missing `LoundryModels` import used by `ActivityEvent`
- removed the accidental self-import from `LocalProcessEnvironment`
- added environment capability reporting for local execution
- added planner validation for build targets and execution/filesystem capabilities
- added structured build diagnostics and build-attempt models
- added retry-path test coverage
- added planner and activity-event tests
- added the repository `VERSION` marker at `0.2.0`

## logic flow

```text
idea
  ↓
planner
  ↓
model provider
  ↓
files + commands
  ↓
environment
  ↓
build
  ↓
verification
  ↓
retry on failure
```

## architecture note

loundrycode remains polyglot by design. swift is not the required language for the whole product. platform shells, orchestration, agents, runtimes, and other subsystems may use different implementation languages behind language-neutral contracts.

## github actions boundary

github actions builds, tests, and packages loundrycode itself. it is not the runtime worker for user-generated projects.

## known limitation

`LocalProcessEnvironment` is an execution adapter, not a hardened sandbox. production environments should provide stronger process, filesystem, network, and resource isolation before executing untrusted generated projects.
